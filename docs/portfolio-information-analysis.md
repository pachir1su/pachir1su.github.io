## 4. 프로젝트 카드 정보 밀도

밀도가 낮은 게 아니라 **축이 빠져 있다.** `projects.json`에 필드 자체가 없는 것:

**Skills 섹션이 프로젝트 tech-stack보다 정보가 적고 신뢰도가 낮은 역전 상태다.**

  능숙한 발표 능력 / 효과적인 프레젠테이션 / 팀 리딩 경험 다수 /
  버츄얼(VTuber) 기술 보유 / 용접 & 납땜. 자기평가 형용사("탁월한", "능숙한",
  "효과적인")가 붙은 항목은 검증이 불가능해 목록 전체의 신뢰를 깎는다.
- "리더십" 카드 4항목 중 3개가 발표 동어반복이다.
- "LLM 활용 능력"은 2026년 기준 변별력이 사실상 없다.
- **역으로, 실제로 쓴 게 확인되는 기술이 Skills에 없다.** Selenium, FastAPI, SQLite,
  PySide6, Discord.py, Gradio, PaperMC, OpenCV, pyautogui, NeoPixel, RCON. 프로젝트

## 9. 모바일 UX

- **내비게이션 표면 5종이 동시에 존재한다.** 상단 fixed navbar + 햄버거 사이드바 +
  하단 도트 네비 + back-to-top + progress bar. 콘텐츠 뷰포트가 크게 줄어든다.
- 하단 도트 네비가 9개(`style.css:3503~`)이고 라벨이 `0.5rem` /
  `max-width: 48px` + ellipsis + `overflow-x: auto`다. 5.5인치에서 가로 스크롤이 나고
  라벨이 잘린다. MBTI · 자격증이 모바일 최상위 네비에 있을 이유가 없다.
- 480px에서 카드 padding이 `28px 16px 18px 44px`인데 왼쪽 44px는 노트 마진선
  **장식**이다. 360px 화면에서 실제 텍스트 폭이 약 250px로 줄어 한글 desc 2줄이
  3줄로 깨진다. 컨셉을 유지한 채 좁은 폭에서만 마진선을 줄일 여지가 있다.
- 부유 아이콘이 모바일에서도 52~64px로 살아있고 드래그 가능하다. hero 텍스트와
  겹칠 여지 + 스크롤 제스처와 경합한다.
- GitHub 통계 SVG 3장이 세로로 쌓여 About이 모바일에서 특히 길어진다.

## 10. 한국어 / 영어 전환 UX

`<html lang>` 동기화(`script.js:997`), localStorage 유지, 메타태그까지 번역 — 기반은
잘 되어 있다. 문제는 **이중 시스템**이다.

- `data-en`/`data-ko` 속성(프로젝트·스킬·수상)과 `script.js #26`의 셀렉터 기반 맵이
  병행한다. 후자는 `.nav-links li:nth-child(2) a`, `.chip:nth-child(1)` 같은
  **위치 의존 셀렉터**라 마크업 한 줄만 옮겨도 조용히 깨진다.
- **이미 깨진 흔적이 있다.** `.mbti-traits-header`, `.mbti-tag`,
  `.mindmap-block .subsection-label`, `[data-nav-section="mindmap-section"]` 4개 키에
  대응하는 요소가 `index.html`에 0개다.
- 상세 페이지 27개의 영어 커버리지가 페이지마다 달라, 메인을 영어로 보다가 상세로
  들어가면 한국어가 섞여 나온다. 언어 상태의 연속성이 깨진다.
- 영문 카피: hero-role이 "혁신의 기업가" → `Innovator`로 바뀌며 원문의 '기업가'가
  사라지고, og:description은 "an **entrepreneur** pursuing innovation beyond profit"이다.
  영어권 채용자에게 entrepreneur로 소개하면 개발자 포지션 신호가 더 약해진다.

## 11. 지나치게 AI가 만든 것처럼 보이는 요소

정확히는 "AI 티"보다 **"기능 목록을 전부 구현한 티"**다. 주석에 이슈 번호가 달려
있어 사람이 붙인 것은 명백하지만, 방문자에겐 아래가 템플릿 · 생성물 신호로 읽힌다.

1. **부수 인터랙션 9종.** 도장 클릭(#7), 드래그 스티커(#8), 그림자 추적(#12),
   키보드 단축키(#13), 마스킹테이프 sweep(#14), 로고 흔들기(#15), 진입 떨림(#16),
   콘솔 이스터에그(#17), 치킨 모드 15클릭(#21). 어느 하나도 정보를 전달하지 않는다.
   1~2개면 개성, 9개면 데모 페이지다.
2. **MBTI 5줄 막대 차트.** 57/84/60/89/76%. 데이터 시각화 형식의 신뢰도로 자기보고
   내용을 전달하는 구조다. 국내에서도 호불호가 크고 채용 맥락에선 마이너스로
   읽힐 수 있다.
3. **자기평가 형용사 6개 이상 반복.** 탁월한 / 능숙한 / 효과적인 / 多 /
   아이디어 뱅크 / 경험 다수.
4. **유사 슬로건 4개 분산.** "이윤을 넘어 혁신을 추구하는 기업가"(hero) /
   "아이디어를 현실로 만드는 혁신가"(quote) / "세상을 바꿀 서비스"(body) /
   "세상에 없던 가치를 창출"(body).

## 14. 학생 포트폴리오 → 실제 개발자 포트폴리오

현재 "학생"으로 읽히게 만드는 요소를 원인별로 정리하면,

1. 축이 '포부'다. 비전 → 역량 → 수상 → 프로젝트. 실무 포트폴리오는 프로젝트가 먼저다.
2. MBTI, 자격증, 학력 배지, 수상 랭킹 01~04는 전부 '지원서' 문법이다.
3. 자기평가 형용사("탁월한", "능숙한", "효과적인", "多").
4. 계획 단계 프로젝트를 목록에 포함(0%, 5%, 20%). 실무 포트폴리오는 미착수 항목을
   게시하지 않는다.
5. 수상 강조 비중이 산출물 강조 비중보다 크다. 수상은 전용 섹션(4카드 + 랭크 숫자 +
   금/은/동 색)인데 산출물은 그 뒤에 있다.
6. 결과 지표 부재. 대회 등수 외의 숫자가 "약 60초" 하나다.
7. 데모 · 스크린샷 부재.

반대로 이미 '실무처럼' 보이는 것도 있다. 실패 프로젝트 공개, 상세 페이지의
"나의 역할" 섹션, `projects.json` 단일 소스 + `build.js` 생성 구조, featured 카드의
문제 / 한 일 / 결과 포맷. 특히 **생성 파이프라인은 사이트 자체가 엔지니어링 증거인데
사이트 어디에도 언급이 없다.** 큰 기회 손실이다.
