## 구현 방식

PR #126에서 `script.js`에 v2.6 호환 레이어를 도입했습니다. 현재 정적 HTML에 남아 있는 이전 마크업을 런타임에서 정규화해 v2.6.0의 사용자-facing 결과를 제공합니다.

PR #127과 #128에서는 이 런타임 상태를 정적 소스로 굳히기 위한 GitHub Actions finalization을 시도했지만, #128 머지 후 예상한 후속 bot 커밋이 `main`에 생성되지 않았습니다. 따라서 해당 자동화 경로는 v2.6.0의 Release gate에서 제거합니다.

큰 `index.html`/`style.css` 전체를 연결 API로 억지로 재작성해 프로젝트 생성 영역을 손상시키는 것보다, 정적 dead-code 제거를 다음 Freeze 단계에서 실제 기기 QA와 함께 처리하는 편이 안전합니다.

## v2.6.x Freeze / Refactor로 이관

- #123/#16 실제 모바일·태블릿·데스크톱 반응형 QA
- reduced-motion, coarse/fine pointer, 다크모드, KO/EN 전환 회귀 QA

## 검증 원칙

- `projects.json`을 프로젝트 카드의 단일 소스로 유지
- `BUILD:PROJECTS` 생성 영역 직접 수정 금지
- PR 내부는 변경 파일 수와 커밋 수를 동일하게 유지하고 파일당 정확히 1커밋
- 공개 저장소에서 개발자 도구·우클릭·텍스트 선택 차단 금지
- `node --check script.js`
- `node build.js` 실행 후 무변경 확인
- `node tools/verify-build.js`
- `git diff --check`
- 실제 브라우저/기기 QA를 하지 못한 항목은 통과했다고 표시하지 않음

## Release gate

Release Hardening PR에서 실패한 finalization 자동화 파일을 제거하고 문서가 실제 구현 상태와 일치하는지 확인한 뒤 `v2.6.0` 태그/Release를 생성합니다. 이후 v2.x는 `v2.6.x Freeze / Refactor` 단계로 전환합니다.
