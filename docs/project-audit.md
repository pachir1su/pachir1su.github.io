## 1. 27개 페이지 전체에 걸친 공통 결함

개별 프로젝트를 보기 전에, **거의 모든 페이지가 같은 방식으로 실패하는 지점**이
있다. 개별 수정보다 이쪽이 비용 대비 효과가 크다.

### 1-1. 「나의 역할」이 역할이 아니라 **작업 목록**이다

현재 형식은 명사 나열이다.

```text
HEALTH_CHECK_PROJECT — 기획 / 라즈베리파이 세팅 / 백엔드 전체 개발 /
프론트엔드 전체 개발 / 물자 파밍 및 조달 / QA & 디버깅 / API 통신 /
일정 조율 / PPT 제작 / Notion 전체 제작 / 그 외 다수   (11개)
```

읽는 사람이 알고 싶은 것은 "몇 가지를 했는가"가 아니라 **"어느 부분의 코드를
당신이 짰는가"**다. 11개를 나열하면 오히려 각 항목의 깊이가 의심된다.
`그 외 다수`는 12개 페이지에 등장하는데, 이 표현은 정보를 0으로 만들면서
"더 있는데 안 적었다"는 인상만 남긴다.

특히 신뢰를 직접 깎는 항목이 있다.

| 페이지 | 문제 항목 |
|---|---|
| `Wall_Sina` | **간식 지원**, 물자 파밍 및 조달 |
| `HEALTH_CHECK_PROJECT` | 물자 파밍 및 조달 |
| `PlantClock` | 식물 **ㄹㅈㄷ** 복지 선풍기, 태양광 전원 시스템**(장식)** |
| `2024_5th_CSRC` | 졸음을 날려버릴 선풍기, 피젯 토이 |

친구에게 보여주는 문서라면 재미있지만, 교수 · 채용담당자가 「나의 역할」에서
"간식 지원"을 읽으면 그 위에 적힌 "아두이노 프로그래밍"의 신뢰도까지 함께
내려간다. 슬랭(`ㄹㅈㄷ`)과 `(장식)` 자백도 같은 작용을 한다.

### 1-2. 1인 개발 프로젝트의 역할 문장이 **완전히 동일한 보일러플레이트**다

```text
"기획부터 개발, 배포까지 전 과정을 단독으로 진행했습니다."
```

6개 페이지에 **글자 하나 다르지 않게** 반복된다 — `CentrifugeAI`,
`HTML_Viewer`, `MultiMind`, `SG_bot`, `file_swordmaster`, `media_swordmaster`.
연속으로 읽으면 즉시 복붙으로 보이고, 이것이 이 포트폴리오에서 가장 뚜렷한
"LLM 냄새 / 템플릿 냄새"다. 1인 개발이라는 사실은 이미 배지로 표시되므로,
이 문장은 정보를 0 추가하면서 신뢰만 깎는다.

### 1-3. 「핵심 기술적 난점」을 서술한 페이지가 사실상 **1개**뿐이다

27개 중 실제로 *무엇이 어려웠고 어떻게 뚫었는지*를 쓴 것은 `MultiMind` 하나다.

```text
pyautogui typewrite() 는 한글 미지원 → pyperclip.copy() + Ctrl+V 로 해결
응답 완료 감지: 전송 버튼 재등장 이미지 인식 (locateOnScreen)
```

`github_rank_insight`가 그다음(이진 탐색 60회, CDF 수식, cloak-preview 헤더)이고,
`2026_U-CAST`가 셋째(`delay()` 대신 `millis()`로 채널 동시 유지)다. **나머지 24개는
"무엇을 만들었다"만 있고 "무엇이 어려웠다"가 없다.** 개발자 독자가 실력을
판단하는 근거가 바로 이 항목인데, 페이지 구조 자체에 그 자리가 없다
(`개요 / 주요 기능 / 나의 역할 / Tech Stack` 4단 고정).

### 1-4. 「주요 기능」이 **기능 덤프**로 흐른다

`raspi-mc-server` 10줄, `koreatechGongjiAgent` 9줄, `CentrifugeAI` 20줄 이상.
특히 `koreatechGongjiAgent`는 포트폴리오 문장이 아니라 **체인지로그 문장**이다.

```text
Storage/Outbox 관측성(v0.20.0-alpha.5) — pending/claimed/dead-letter,
lease age, DB/WAL 상태를 JSON·SQLite 권위 backend에서 실시간으로 읽어
관리자 디스코드 상태와 JSON 진단 CLI로 확인
```

이 문장은 이미 그 프로젝트를 아는 사람만 읽을 수 있다. 처음 보는 사람에겐
"많이 만들었구나"까지만 전달되고 **무엇이 핵심인지는 오히려 가려진다.**

### 1-5. 「결과」 칸이 구조적으로 없다

페이지 4단 구조에 결과 자리가 없어서, 수상작(`nonofire`, `2024_5th_CSRC`,
`2026_U-CAST`)만 「주요 기능」 마지막 줄에 수상을 끼워 넣는 식으로 처리된다.
운영 중인 프로젝트(`koreatechGongjiAgent`, `raspi-mc-server`)조차 사용자 수 ·
가동 기간 · 처리량 같은 숫자가 하나도 없다.

### 1-6. 증거(사진 · 영상 · 데모)가 27개 중 2개

`2026_U-CAST`(사진 2장)와 `nonofire`(YouTube)뿐이다. 특히 **하드웨어
프로젝트 7개 중 사진이 있는 것이 1개**라는 점이 치명적이다. 도어락 ·
NFC 출석기 · 식물 타이머 · 해안 장벽 모형 · 졸음 감지기는 **사진 한 장이
설명 열 줄보다 강한** 종류의 프로젝트인데, 전부 텍스트로만 있다.

### 1-7. 기간이 없다

`tech_and_society`(2026년 5월)만 기간이 적혀 있다. 나머지는 연도 그룹만
있어서, 3일 만든 과제와 6개월 운영 중인 시스템이 같은 무게로 읽힌다.

### 3-3. `Sibal_Life_Smoking` — 숨김이 완결되지 않았다

공개 저장소이므로 채용담당자가 GitHub에서 `projects/` 목록을 열면 바로 보인다.
